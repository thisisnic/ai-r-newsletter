# AI Tooling & R Ecosystem Weekly Digest

A busy week for LLM CLI tooling, a notable open-source language release, and a few pieces worth sitting with on how we think about code and AI assistance.

---

## LLM Tooling

**[llm 0.32.1](https://simonwillison.net/2026/Aug/21/llm/)** — date unavailable

A patch release for Simon Willison's `llm` command-line tool. Worth tracking if you run it in automated pipelines or scripts where stability matters.

**[llm 0.33](https://simonwillison.net/2026/Aug/22/llm/)** — date unavailable

The minor version bump following quickly on 0.32.1, suggesting active development velocity. New features in point-three releases of `llm` tend to touch model management and plugin interfaces, making this relevant for anyone building on top of the tool.

**[llm-openrouter 0.7](https://simonwillison.net/2026/Aug/21/llm-openrouter/)** — date unavailable

An updated plugin connecting the `llm` CLI to OpenRouter's model aggregation API. OpenRouter gives access to a wide range of models through a single endpoint, and keeping this plugin current matters if you use it for model comparisons or cost routing.

**[A shot-scraper-style JSON API on Bun 1.4's new Bun.WebView](https://simonwillison.net/2026/Aug/20/bun-webview-json-api/)** — date unavailable

Willison explores using Bun 1.4's new `Bun.WebView` to build a headless-browser JSON API in the style of his `shot-scraper` tool. Practically useful for anyone who needs to extract structured data from JavaScript-heavy pages without standing up a full Playwright or Puppeteer stack.

## Models & Benchmarks

**[Qwen 3.8 27B is excellent, but it defaults to wildly overthinking things](https://simonwillison.net/2026/Aug/16/qwen-38-27b/)** — date unavailable

A hands-on assessment of Qwen 3.8 27B, which apparently performs well on reasoning tasks but has a tendency to generate far more chain-of-thought output than the problem warrants. Relevant if you're evaluating open-weight models for tasks where token efficiency matters.

**[Qwen 3.8 27B scores 52 on the Artificial Analysis Intelligence Index](https://simonwillison.net/2026/Aug/17/qwen-38-27b-scores-52/)** — date unavailable

Follow-up benchmark context for the same model. A score of 52 on the AA Intelligence Index puts it in competitive territory among open-weight models at this size class, useful data point for anyone doing model selection.

## Security & Sandboxing

**[smolmachines / smolvm as a sandbox for untrusted Python & JavaScript](https://simonwillison.net/2026/Aug/19/smolmachines-untrusted-sandbox/)** — date unavailable

A look at `smolvm`, a lightweight virtual machine approach to sandboxing untrusted code execution in Python and JavaScript. As LLM-generated code execution becomes more common in agent workflows, sandboxing options like this deserve attention from anyone building those systems.

## Open Source

**[Mojo is now open source](https://simonwillison.net/2026/Aug/18/mojo-is-now-open-source/)** — date unavailable

Modular's Mojo language, pitched as a Python-compatible systems language with performance characteristics suited to ML workloads, has gone open source. Whether it gains traction in the ML tooling space over the next year is worth watching, particularly for practitioners who work at the Python/performance boundary.

## Commentary

**[Conceptual integrity and counting lines of code](https://simonwillison.net/2026/Aug/19/conceptual-integrity-and-counting-lines-of-code/)** — date unavailable

A piece engaging with Fred Brooks-era ideas about conceptual integrity in software design, prompted by the AI-assisted coding moment. The argument — roughly, that coherence matters more than volume — is a reasonable counterweight to the "ship more code faster" framing that dominates AI coding discourse.

**[More than just code review](https://simonwillison.net/2026/Aug/22/more-than-just-code-review/)** — date unavailable

Reflects on what AI assistance in software development actually changes about the review process. The framing goes beyond syntax and correctness into questions of intent and design, which is where most current tooling still falls short.

**[ChatGPT search now uses the site: operator at scale](https://simonwillison.net/2026/Aug/20/chatgpt-search-now-uses-the-siteoperator-at-scale/)** — date unavailable

Notes that ChatGPT's search feature has started issuing large numbers of `site:`-restricted queries against specific domains. Has implications for anyone running web properties that feed into AI training or retrieval pipelines, and raises questions about crawl load and attribution.

**[We Tracked a Shipment of Rare Books. It Ended at an Amazon AI Training Facility](https://simonwillison.net/2026/Aug/17/we-tracked-a-shipment-of-rare-books-it-ended-at-an-amazon-ai-tra/)** — date unavailable

Investigative reporting linked by Willison tracing physical book acquisitions to Amazon's AI training operations. A concrete illustration of how training data supply chains work in practice, and the scale at which physical-to-digital pipelines are operating.
